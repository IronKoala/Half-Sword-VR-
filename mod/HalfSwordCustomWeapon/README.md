# HalfSwordCustomWeapon (test)

A test of an **uncooked** weapon part: a model file is turned into part of a weapon while the game runs, with no editor and no cooked asset.

## What it does

Hold a weapon in the right hand and press **F9**. The mod then:

1. **Loads the model.** It reads `test_blade.obj` from this folder.
2. **Swaps the collision.** It builds a runtime static mesh that is the model's bounding box, with box collision, and puts it in the weapon's `Head` slot.
   - The `Head` component keeps the game's hit binding, mass and `Tip` damage points, so hits go through the game's own damage code.
   - The box itself is hidden.
3. **Shows the model.** It attaches a procedural mesh with the model to the head, as a visual only, using the head's original material.

The log is `CustomWeapon.log` in this folder. Settings are in `CustomWeapon.ini` and are read again on every key press.

## Known limits of this test

- **Collision is the model's bounding box.** A straight blade fits it well; a curved or hooked model will not.
- **Damage points stay where the old head had them.** `fit_to_original=1` scales the model so its end lands at the old tip.
- **There is no undo.** Drop the weapon and take a new one to get a normal weapon back.
- **The swap is not saved.**

## Install

1. Copy `dlls/main.dll`, `CustomWeapon.ini` and `test_blade.obj` to `Half Sword/HalfswordUE5/Binaries/Win64/Mods/HalfSwordCustomWeapon/`.
2. Add an empty `enabled.txt` in that folder, or add `HalfSwordCustomWeapon : 1` to `Mods/mods.txt`.

`test_blade.obj` is generated by `tools/make_test_blade.py`. It is plain numbers, not a third-party model.

## Making a model

Two converters write the files the mod reads (`<name>.obj`, `<name>_collision.obj`, `<name>.txt`, and
when the source has a material `<name>_BaseColor.png`, `_Normal.png`, `_ORM.png`). Put them in the mod
folder and set `model=<name>.obj` in `CustomWeapon.ini`. No models ship with this repo.

- `tools/model_to_weapon.py <model> <out> [--units m|cm|mm|in] [--mass-kg KG]`: any sword model trimesh
  can read (OBJ, glTF/GLB, ...). It finds the long axis, the guard, which side is the blade, the grip and
  pommel and the edge direction, and prints each result so a wrong guess shows (`--flip`,
  `--handle-bottom-cm` override). Without `--mass-kg` the mass is estimated from the model's volume.
- `tools/bs_weapon_export.py <bundle> <item json> <prefab> <out>`: a Blade & Sorcery weapon (e.g. from
  the Medieval MegaPack), using its own handle, mass and textures.

Shared code: `tools/weapon_parts.py`. Needs `pip install trimesh numpy scipy pillow` (and `UnityPy` for B&S).
